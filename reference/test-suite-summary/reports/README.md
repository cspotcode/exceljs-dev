# Test suite summary

Generated by [`generate-reports.sh`](../generate-reports.sh). Re-run that script to refresh these files after tests change.

## CI

`.github/workflows/tests.yml` runs, per push/PR:

- **test** job (matrix of Node 10–20.x × ubuntu/macOS/windows): `npm install && npm test`
- **benchmark** job: `npm run benchmark` (not a correctness test suite; measures perf impact)
- **typescript** job: `tsc index.d.ts` (type-checks the published `.d.ts`, does not run `spec/typescript/`)

## `npm test` script chain

`npm test` → `test:full` → in order:

1. `npm run build` (grunt: babel + browserify + terser + exorcise + copy — produces `dist/exceljs.js` etc.)
2. `npm run test:unit` — see [unit-tests.md](unit-tests.md)
3. `npm run test:integration` — see [integration-tests.md](integration-tests.md)
4. `npm run test:end-to-end` — see [end-to-end-tests.md](end-to-end-tests.md)
5. `npm run test:jasmine` (`grunt jasmine`) — see [jasmine-browser-tests.md](jasmine-browser-tests.md)

## Scripts that exist but are NOT run by CI

- `test:dist` (mocha over `spec/dist/`, requires `npm run build` dist output) — release/manual verification only
- `test:typescript` (mocha + ts-node over `spec/typescript/*.spec.ts`) — not wired into CI; CI instead runs `tsc index.d.ts` directly
- `test:manual` — starts an Express app for manual/interactive testing (`spec/manual/app.js`), not automated
- `test:es5` / `*:es5` variants, `test:all`, `test:native`, `test:version` — used for release verification (`preversion` hook), not CI
